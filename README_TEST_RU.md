# Расчётчик: запуск и проверка

Проект исправлен на основе версии из `C:\Users\User\Music\mephilaborant`.
Исходная `.venv` ссылается на отсутствующий Python. Поэтому добавлен официальный
переносимый Python 3.12.10 в `.runtime`: он использует уже установленные библиотеки
из `.venv/Lib/site-packages`. Для запуска не нужна установка Python в систему.
Не удаляйте `.venv`: там лежат библиотеки. `.runtime` не является полноценным venv.

Откройте PowerShell и выполните:

```powershell
cd C:\Users\User\Music\mephilaborant
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 ui
```

Интерфейс: http://127.0.0.1:8501. Остановка — Ctrl+C в этом терминале.
Для тестов замените `ui` на `check`; для консольного примера — на `demo`.
`api` запускает API на http://127.0.0.1:8000/docs, `up` — API и интерфейс вместе.
`setup` проверяет версии зависимостей и пересобирает BM25 по имеющимся PDF;
`index` пересобирает настроенный индекс. Отсутствующих скриптов эти команды больше не вызывают.

## Проверка без модели

Выберите «Повторные измерения» и «Текст таблицы». По умолчанию подставлен период
маятника около 2 секунд. В поле номера работы укажите `1.3`, а в задании — `L = 1 м`.
Формула `g = 4*pi**2*L/T**2` будет найдена в имеющемся образце методички автоматически.
После нажатия «Посчитать» ожидается `g ≈ 9.87 м/с²`.
Приборную границу можно задать отдельным полем: `T = 0.01 с`.

Для МНК выберите «Зависимость y(x), МНК». По умолчанию подставлена таблица с
наклоном около 2 м/с. Можно переставить строки — результат сохранится.
Оси выбираются явно. Пропуск `?` или пустая ячейка должен привести к просьбе
исправить таблицу, без удаления и сдвига отдельных значений.

Погрешности нескольких величин вводятся отдельно: `T = 0.01 с; L = 1 мм`.
Если единица не указана, граница задана в исходных единицах столбца.
Если величина в этом поле не указана, её приборная составляющая считается нулевой.
Заданные в тексте константы (`L = 1 м`, `g = 9.81`) считаются точными.
Для учёта неопределённости величины используйте столбец её повторных измерений.

Числа считает Python независимо от провайдера. `check` всегда использует mock
и не обращается к внешним моделям. Результаты синтетического набора записываются
в `artifacts/metrics.md` и `metrics.json`. Это небольшой регрессионный набор,
а не доказательство показателей ≥95% и ≥90% на реальных работах МИФИ.
Для этих показателей ещё нужен отдельный корпус реальных эталонов и фото.

Итог косвенного расчёта выделяется в начале ответа: например,
`Ускорение a = 1.002 ± 0.033 м/с²`. Название определяется по явной связи
термина с обозначением в выбранной методичке; источник и фраза сохраняются
в JSON (`quantity_name_source`, `quantity_name_evidence`). Одна буква не
определяет физический смысл: E может быть модулем Юнга или ЭДС.
Если название не поддержано или определения противоречат друг другу,
остаётся обозначение величины. При формуле без левой части — «Результат».
Подробности раскрываются в разделе «Ход расчёта и погрешности».

## Модели и фото

Существующая `.env` сохраняется. Названия текстовой и визуальной моделей
читаются из `LLM_MODEL` и `LLM_VISION_MODEL`; провайдер — из `LLM_PROVIDER`.
Для Qwen-VL замените только название визуальной модели на доступное у вашего
провайдера. Проверка `provider` отправляет один реальный текстовый запрос.
Доступность конкретных бесплатных моделей в этой доработке не проверялась.

По умолчанию выбран ввод фотографией. Укажите номер работы, загрузите PNG/JPG
и нажмите «Посчитать». Ручной ввод доступен переключателем «Текст таблицы».
Оба пути используют один поиск по PDF. В результате можно раскрыть раздел
«Теория и методика из PDF» и увидеть фрагменты со ссылками на страницы.

Для фото нужна визуальная модель; mock честно отказывает. Некорректный JSON,
пропуски и столбцы разной длины не допускаются к расчёту. После распознавания
показаны использованные числа в СИ: обязательно сверьте их с журналом.
Ошибка реального провайдера больше не заменяется молча mock-ответом.
Формулу укажите текстом либо задайте номер работы для поиска в методичке:
извлечение формулы непосредственно с фотографии здесь не реализовано.

## Методика и границы

Сначала считаются стандартные неопределённости: СКО среднего и приборная
граница/√3. Затем они объединяются в квадратурах; эффективное число степеней
свободы определяется формулой Уэлча—Саттертуэйта и применяется t-фактор.
Для косвенного результата передаются стандартные составляющие и их степени
свободы, а расширение выполняется после распространения через производные.
Выводимая вероятность `P ≈ 0.95` приблизительная, особенно при доминировании
равномерной приборной составляющей. Это общий метод, который надо согласовать
с требованиями методички конкретной лабораторной работы.

Основание: [NIST: объединённая стандартная неопределённость](https://www.nist.gov/pml/nist-technical-note-1297/nist-tn-1297-5-combined-standard-uncertainty),
[NIST: коэффициенты охвата](https://www.nist.gov/pml/nist-technical-note-1297/nist-tn-1297-appendix-b-coverage-factors).

МНК — линейный, с точным x и независимыми ошибками y одинаковой дисперсии.
Приборная стандартная неопределённость y задаёт нижнюю границу дисперсии остатков.
Для погрешности x и для косвенной формулы с обоими коррелированными коэффициентами
k и b сейчас выдаётся явный отказ: нужна отдельная модель ковариации/регрессии.
Промахи повторных измерений проверяются критерием Шовене, точки зависимости —
по внешне стьюдентизированным остаткам с поправкой Бонферрони. Подозрительные
точки МНК не удаляются автоматически; несколько промахов могут маскировать друг друга.

## Установка на другом компьютере

Установите Python 3.12, создайте `.venv`, затем `python -m pip install -r requirements.txt`.
Если папка `.runtime` отсутствует, `start.ps1` использует рабочую `.venv`.
Официальный источник добавленного переносимого интерпретатора:
[Python 3.12.10](https://www.python.org/downloads/release/python-31210/).

Предыдущее замечание о неверном `parents[2]` было ошибочным: в `src/app/config.py`
это правильный корень проекта. В версии из «Музыки» `app.data.expand` тоже уже был.
